## 2026-04-13 - Lexicographical Date Sorting & Next.js searchParams Optimization
**Learning:** For performance-critical code involving ISO 8601 timestamps, direct lexicographical string comparison using operators ('<', '>', '===') is ~30x faster than 'Date' object instantiation. Similarly, accessing `request.nextUrl.searchParams` directly prevents redundant `new URL(request.url)` parsing and heap allocations. Reusing single Date instance via mutating setters further reduces the memory footprint.
**Action:** When working on date-based filters or sorting arrays of ISO-8601 datetimes, avoid parsing into Date objects inside `.filter` and `.sort` loops. Use native string operators directly and reuse Date instances for boundary calculations. Always unstage and restore compiler-driven modifications to `tsconfig.json` or `package-lock.json`.
